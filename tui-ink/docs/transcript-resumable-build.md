# 首次索引分批构建与持久断点

首次历史索引重建现在按完整校验的来源分段提交进度。默认累计 64 段，或距上次提交达到 250 ms 后，在下一个完整分段边界提交；最后一段随完整索引一起发布。`SPAWN_TRANSCRIPT_BUILD_BATCH_SOURCES` 可设为 1–1024，按请求读取，默认 64。250 ms 是触发条件，不是大分段的提交时限。

## 持久状态与恢复

同一笔 SQLite 事务写入消息行、消息计数和构建断点，使用 synchronous=FULL。构建状态为 `transcript-build-v1`，保存已验证序号、末尾哈希、目标序号、消息计数和来源摘要链。来源清单按批追加到 `transcript_build_sources`，每行有摘要及顺序编号；每次提交只追加新来源，不重复写此前全部清单。

重新打开后校验元数据根摘要、清单行摘要及摘要链、来源连续性、边界哈希、消息计数和当前来源指纹。验证通过，从已提交序号后继续读取；未提交批次由 SQLite 回滚。归档清理或来源表示变化时按既有校验重新映射；无法证明同一前缀时重建。原始归档损坏仍拒绝返回历史。

构建中的数据库可以有已提交的完整前缀，分页 API 仍等待完整目标边界校验后才返回页面。最终事务把状态发布为 `transcript-v2` 并清除构建清单。中断最终发布时会回到上一个完整断点。缓存/清单损坏按可重建缓存处理，原始事件、记忆、目标版本、预算与历史费用快照不改写。

配额不足时停止新增断点提交，保持当前未提交结果供本次完整读取使用；完成时沿用索引配额检查与清理。配额为 0 时不保留断点。不会为提交一批而删除仍待构建的消息，或把不完整索引当作已完成页。

## 进度与执行

进度显示“重建索引 / 已保存构建断点 / 续建索引”和恢复序号；完成后显示从哪个断点续建。返回 `resumedFrom`、`checkpoints`、`checkpointedThrough`、`checkpointRetained`，可区分恢复位置、本次提交数及配额状态。`visited` 只统计本次实际消费的历史事件，不含恢复时检查元数据的成本。

索引仍在独立读取线程中执行。PM 执行、沟通、需求变更取消与重启恢复沿用共享 SessionController；索引不派发任务。改变目标后的新增事件在后续查询增量读取，当前 UI 继续显示最新执行状态。返回最新或关闭后忽略迟到的构建进度。

## 强杀锁修复

真实强杀测试发现旧的 open(wx) → 写 PID 存在空锁窗口，可能让重启恢复被阻塞。现在先在独立目录写好 owner，再原子重命名发布非空目录锁。该方案在本机 E 盘 exFAT 上验证，不依赖它不支持的硬链接；旧的有效 PID 文件锁仍能识别，活跃或无法识别的所有者保持保护。

本次扫描复用已准备的锁记录，批次间仅短暂取得写锁。正常结束清理准备目录；强杀留下的准备目录不会占据共享锁，保留期清理仅删除已确认 PID 退出且目录内容属于此协议的旧草稿，不递归删除未知内容。

## 剩余限制

断点位于完整来源分段边界。未完成的当前批次需要重读，超大单个 gzip 归档内部尚不能直接跳转续建；它必须先读到尾部并校验摘要/CRC。首次完整构建仍须验证全部来源，提交断点增加了持久化写入，不能保证首次不中断时更快。恢复仍检查来源元数据及持久清单，源码表示变化可能需要额外校验。配额关闭、损坏或未通过校验的断点不能用于续建。
