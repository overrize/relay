# 历史分页索引与虚拟显示窗口

运行入口仍是 `E:\spawn-work\relay.cmd --ui=native`，未切换默认界面。

## 分页读取

历史消息单独索引到工作区 `.spawn/transcript-cache/index.sqlite`。复用审计缓存的来源清单、序号/哈希锚点和归档校验逻辑，数据库、内容和配额与审计统计分开；Linux 下消息缓存文件权限为 0600。

- 初次查询建立消息序号 B-tree；后续按 `seq < before ORDER BY seq DESC LIMIT n+1` 取页。
- 来源未改变时不重放旧事件，也不解压旧归档；新增事件只增量更新索引。工作线程每次独立启动，索引跨进程/重启复用。
- 分段旋转/保留期清理可验证并重映射来源；无法证明同一来源时重建。丢失或损坏的缓存从保留记录重建，缓存行有摘要校验；原始归档损坏则拒绝返回部分历史。
- 完整查询在后台线程中运行，不占 PM 事件循环。SQLite 事务发布索引，进程中断不发布半份索引。
- 默认缓存配额 256 MiB，可通过 `SPAWN_TRANSCRIPT_INDEX_MAX_BYTES` 调整；超额或来源并发变化时会提示未保留索引。配额为 0 是显式关闭持久缓存，会重新扫描。
- 返回 `index.mode / visited / retained / projectionBytesRead`，区分重建、增量与未保留状态。单条传输内容最大约 24k 字符，原始事件保持完整。

归档指纹加入文件身份和时间元数据，已建索引后修改原归档也会触发重新校验；不信任仅保留清单中未变的摘要。主会话、预算和原始费用快照不随缓存变化。

## 虚拟显示

`VirtualTranscript` 只给终端布局返回当前可见行，避免工具库为完整文档重复布局或遍历历史行。消息换行高度按宽度缓存；后台新增消息只测量新增块，滚动使用块高度偏移二分定位。换行结果 LRU 最多 24 个块，高度元数据保留两个宽度，最近消息块元数据缓存有界。

Native UI 最多保留 1024 条归档消息的显示窗口，实时显示仍取最近 150 条。继续向前翻页时卸载窗口里较新的归档文本，明确显示提示；原记录和分页索引不删除。`/latest` 返回最近消息；当窗口发生卸载时，Alt+End 同样返回最近记录。草稿、光标、当前目标和 PM 执行均不随显示窗口卸载。

PageUp/PageDown、自定义翻页键、滚轮都操作虚拟窗口。旧页加载完成不会隐藏之后到来的实时输出；返回最新或退出后，迟到的分页结果不会覆盖当前视图。会话快照直接取末尾 150 条，避免先复制全部实时消息数组。

## 仍有开销的边界

首次建索引、索引丢失/无法校验后的重建仍需读取保留历史；来源清单及文件元数据检查随分段数增长。宽度改变需重新测量当前有界窗口，首次加载一页需测量新消息，不保证任何机器上固定耗时。

无限历史不全部驻留 UI；跨未加载范围的全文查找继续使用历史检索，显示时先加载对应页。旧 UI 和运行时内部的其他长期状态未在本轮整体改成虚拟容器。Claude 未改，Copilot 仍待账号验证。
