# 元数据增量校验与大归档流式读取

本轮在有界历史读取线程中加入分段元数据缓存。监视 memory / segments 目录的文件变更，热页检查变更来源及当前页（含下一页判断行）所涉及的归档；活动日志始终直接检查。目录身份也逐次验证。未知通知、目录替换、watch 错误或平台不支持时清空缓存或回退全量检查。活跃查询期间每 5 秒执行全量复核，闲置后下一次查询复核；不是后台永久轮询。

这是有检测延迟上界的显示缓存优化：通知若静默漏报，未显示归档的改动可能到下一次定期复核才发现；当前页来源不依赖通知。不是每页都重新认证全部归档。审计和执行恢复的原有校验路径保持不变。返回 metadataMode、validationWindowMs、metadataChecks，便于区分当前检查方式。首次启动复用基线恢复刚取得的归档 stat，避免重复检查。

大归档按 gzip 数据流读取和逐条解析，增量计算原格式摘要，并检查条数、序号范围及 gzip 尾部。超过 64 KiB 压缩数据、至少 512 条事件，或 gzip 声明解压后超过 1 MiB 时使用流式路径；低压缩体积、高压缩比归档也覆盖。小归档保留批量解码路径。非规范化旧 JSON 头回退原有完整校验解码器。已读内容仅写 SQLite 未提交事务，最终摘要、CRC 或边界不符则回滚，不返回部分页。

首次重建显示校验来源、重建阶段及已校验条数，每 100 ms 最多一次进度更新。输入区保持可用，返回最近记录或关闭后忽略迟到进度。停止消费时等待在途文件读取结束，描述符始终由调用方关闭。

## 同机对照

上一提交 fcc335a 与本轮使用相同离线夹具、分别启动读取进程：

| 场景 | 上一版 | 本轮 |
| --- | --- | --- |
| 1000 段，热页元数据检查 | 1000 次 | 81 次 |
| 1000 段，热页耗时 | 49–53 ms | 23–25 ms |
| 1000 段，首次完整重建 | 646 ms | 633 ms |
| 单归档 3002 事件，完整重建 | 317 ms | 317 ms |
| 单归档独立解码峰值 RSS | 158 MiB | 67 MiB |
| 单归档独立解码耗时 | 129 ms | 120 ms |

首次重建提速较小，单归档完整重建没有测到提速；主要收益是热页检查次数、峰值内存和可见进度。结果受文件缓存、磁盘和调度影响，不承诺固定时延。当前页来源检查数取决于事件分布。统计中的 metadataChecks 不包含所有运行时基线/目录 stat。

复现：`node scripts/benchmark-transcript27.mjs <离线夹具> --cold`；大单归档夹具可由 `node scripts/benchmark-transcript.mjs 3000 134217728` 创建。分别运行 `node --expose-gc scripts/benchmark-archive28.mjs <离线夹具> whole` 和 `stream` 比较独立解码。日志保留在 `.test-tmp/native28-compare-old1000.log`、`native28-final1000.log`、`native28-compare-oldbig.log`、`native28-big-after.log`、`native28-memory-whole.log` 和 `native28-memory-stream.log`。

## 验证与边界

回归覆盖真实文件通知、定期复核、不支持/错误通知回退、大归档中文和转义跨块、尾部损坏回滚、旧格式回退、高压缩比、描述符所有权及迟到进度。旧分页、索引损坏修复、要求变更取消、重启恢复继续验证。

Windows PTY 在 3000 条消息单归档上删除可重建缓存后操作冷重建，显示 0 / 998 / 2083 条进度；中文草稿、Alt+N 连续翻页、PageUp/PageDown、滚轮、Alt+End 与退出通过。真实 Kimi PM / DeepSeek Worker：执行中追问和读取历史、取消旧目标、新任务验收、强杀后恢复与累计 7 次请求通过，证据 `.test-tmp/native23-live-7gJntg/verification.json`。

首次重建仍需完整读取并校验保留历史，尚无可恢复的分批建库断点；5 秒全量复核仍随分段数增长。单条超大事件及非规范旧归档回退仍可能占较多内存，审计/备份的完整解码尚未整体迁入流式路径。测试中既有 watchdog 的 10 秒进程等待在负载下超时，本轮只给该测试的外部进程清理等待增加到 30 秒，仍断言进程终止、cancelled 和 owner-lost，生产清理策略未改。

本地验证：全量 905 项，898 通过、0 失败、7 个既有 TODO；headless 82 项通过，typecheck 与 build 通过。watchdog 文件 14 项定向回归通过。Linux、Windows CI 随最终提交核验。
